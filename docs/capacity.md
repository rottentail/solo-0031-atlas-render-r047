# 容量验证

`scripts/capacity_validation.py` 对真实 HTTP 进程施加可重复负载，验证有界队列
（最多 64 个未结束任务）与渲染工作预算（编译工作量不超过 4 千万图层像素）在
过载、取消、重试和进程重启下的行为。仅使用 Python 标准库，服务端为仓库内 Go 服务。

## 运行

```sh
python3 scripts/capacity_validation.py                 # 临时目录，结束自动清理
python3 scripts/capacity_validation.py --workdir var/capacity --report var/capacity/report.json
```

脚本先 `go build ./cmd/atlas`，再在独立状态目录启动服务；结束后停止进程。
任一硬性断言失败时进程退出码非 0，并在报告里保留失败原因；`--workdir` 指定的
目录不会被删除，便于检查 `state.json` 与 `server.log`。

## 负载构成

| 场景 | 画布 | 图层 | 单任务成本（图层像素） | 用途 |
|---|---|---|---|---|
| `small` | 320×240 | 2 | 153,600（scale 2 为 614,400） | 健康查询对照、被拒键重放 |
| `fill8` | 1024×1024 | 8 | 8,388,608 | 队列饱和突发（实测单任务约 0.85s） |
| `fill12` | 1024×1024 | 12 | 12,582,912（scale 2 为 50,331,648） | 高倍输出越预算 |
| `big16` | 1500×1500 | 16 | 36,000,000（scale 2 为 144,000,000） | 长任务取消、崩溃恢复（实测约 3.2s） |
| `over18` | 1500×1500 | 18 | 40,500,000 | 普通倍数即越预算 |

负载参数经独立探测（同目录脚本外的实测）校准：饱和任务足够快，使 80 个并发请求
在约 1 秒内完成并稳定打满 64 槽；长任务足够慢，使 running 取消和崩溃恢复有
稳定的观测窗口。所有键名、场景结构和提交顺序在每次运行中固定，因此结果可重复。

## 验证阶段与通过依据

1. **预算前置拦截**：3 个越预算请求（含高倍输出）在接受前返回 `429/capacity`，
   持久状态中零收据、零任务；预算内对照请求全部 202 并成功。被预算拒绝的键
   从未落收据，随后用预算内请求重放被接受。
2. **队列硬边界**：80 键屏障并发突发 + 主动补灌直到收到 429。硬性依据是任何
   时刻 pending ≤ 64（采样器每 10ms 观测），满载后的追加提交全部 429 且不产生
   新收据。接受数本身依赖时序（渲染期间槽位会释放），因此不作为固定断言。
3. **健康查询不被拖死**：持续补压维持接近满载的同时，40 次 `/healthz` 与
   `/v1/status` 探测零失败，延迟写入报告（实测 p95 亚毫秒到十几毫秒）。
4. **取消**：分别取消 queued 与 running 任务，均落 `cancelled`；running 取消后
   复查确认没有迟到的成功结果覆盖，取消任务不持有 artifact；取消幂等。
5. **重试**：cancelled 任务重试后 `attempt` 递增并沿用固定输入；成功任务重试
   返回 409；队列满载时重试返回 429 且不破坏状态，槽位释放后重试成功。
6. **被拒键重试**：容量恢复后，所有仍未消费的被拒键用相同键重试均被接受，
   每张收据唯一指向一个任务，不存在无收据任务。
7. **重启对账**：SIGKILL 强杀后重启，收据集合、任务终态、attempt 与每个成功
   任务的 PNG 摘要逐一对账一致；另做一次 running 中强杀，验证恢复为 queued、
   attempt 不增、发出 `job.recovered` 事件并最终成功。

每个阶段都运行收据—任务—结果三角不变量检查：每张收据指向存在的任务且指纹
匹配；每个任务都有收据；成功任务必有结果且反向引用一致；非成功任务不持有结果。

## 资源测量

报告 `measurements` 字段记录：提交与健康查询的延迟分位（min/avg/p95/max）、
进程峰值 RSS（采样 `/proc/<pid>/status`）、峰值状态文件字节数和 CPU 占用比。
硬性资源门槛为峰值 RSS ≤ 256 MiB、峰值状态文件 ≤ 16 MiB；实测在 170 个左右
任务规模下峰值 RSS 约 120–130 MiB、状态文件约 7 MiB。门槛写在脚本的
`passCriteria` 中，调整规模时需同步复核。

完整一次运行约 3 分钟，结果与逐阶段明细写入 JSON 报告，控制台同步输出
PASS/FAIL 清单。
